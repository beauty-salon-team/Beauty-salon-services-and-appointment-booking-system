# مستندات معماری پروژه HomeStore

## ۱. انتخاب معماری (Architecture Choice)
با توجه به اینکه تیم ما کوچک است (۳-۴ نفر) و پروژه در فاز MVP (حداقل محصول قابل ارائه) قرار دارد، معماری **Layered Monolith** (تک‌پارچه لایه‌ای) را انتخاب می‌کنیم.

**دلایل انتخاب:**
*   **سادگی و سرعت توسعه:** برای تیم‌های کوچک، مونولیت سرعت راه‌اندازی و توسعه را بالا می‌برد.
*   **هزینه و پیچیدگی کمتر:** نیازی به مدیریت سرویس‌های جداگانه (Microservices) و پیچیدگی‌های شبکه‌ای نیست.
*   **جدایی مسئولیت‌ها (Separation of Concerns):** با استفاده از لایه‌بندی، کدها سازماندهی می‌شوند و نگهداری آن‌ها آسان‌تر است.

## ۲. لایه‌های سیستم و تکنولوژی‌ها
طبق مدل لایه‌ای (Layered Architecture) در اسلاید ۱۲ و ۱۶ جلسه ۴:

| لایه (Layer) | مسئولیت | تکنولوژی پیشنهادی |
| :--- | :--- | :--- |
| **Presentation (UI)** | تعامل با کاربر، نمایش صفحات | React.js / Next.js |
| **Business (Logic)** | منطق کسب‌وکار (محاسبه سبد خرید، اعتبارسنجی) | Node.js + Express |
| **Data (Access)** | دسترسی به دیتابیس، کوئری‌ها | PostgreSQL + ORM (مثل Prisma یا Sequelize) |

## ۳. طراحی رابط برنامه‌نویسی (API)
ارتباط بین Frontend و Backend از طریق **REST API** انجام می‌شود.
*   `GET /api/products` : دریافت لیست محصولات
*   `GET /api/products/:id` : دریافت جزئیات یک محصول
*   `POST /api/cart` : افزودن به سبد خرید
*   `POST /api/orders` : ثبت سفارش نهایی

## ۴. تصمیمات کلیدی (Trade-offs)
*   **امنیت در برابر سرعت توسعه:** در فاز MVP از احراز هویت ساده (JWT) استفاده می‌کنیم تا تمرکز روی منطق فروشگاه باشد.
*   **مقیاس‌پذیری:** فعلاً نیازی به معماری Microservice نداریم، اما کدها را به گونه‌ای می‌نویسیم که در آینده قابل جداسازی باشند.
