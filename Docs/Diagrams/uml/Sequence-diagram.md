# Sequence Diagram — سیستم سالن زیبایی

## ۱. مقدمه

این دیاگرام ترتیب تعاملات بین اجزا را در یک سناریو نشان می‌دهد.

## ۲. سناریو: رزرو نوبت

### ۲.۱ Actors
- **مشتری** — کاربر
- **Frontend** — React
- **Backend** — Express
- **Database** — PostgreSQL

### ۲.۲ ترتیب

1. مشتری روی دکمه «تایید نهایی رزرو» کلیک می‌کند.
2. Frontend درخواست POST به `/api/appointments` می‌فرستد.
3. Backend درخواست را اعتبارسنجی می‌کند (آیا کاربر لاگین است؟ آیا فیلدها کامل هستند؟).
4. Backend زمان انتخاب شده را در Database چک می‌کند (آیا قبلاً رزرو نشده است؟).
5. Backend نوبت را در Database ثبت می‌کند.
6. Backend وضعیت زمان را به «رزرو شده» تغییر می‌دهد.
7. Backend پیام موفقیت و کد رهگیری را برمی‌گرداند.
8. Frontend پیام موفقیت را به مشتری نشان می‌دهد.

## ۳. سناریو: مشاهدهٔ لیست خدمات

1. مشتری وارد صفحه اصلی (خدمات) می‌شود.
2. Frontend درخواست GET به `/api/services` می‌فرستد.
3. Backend لیست خدمات را از Database می‌خواند.
4. Backend لیست را به صورت JSON برمی‌گرداند.
5. Frontend لیست خدمات و قیمت‌ها را نمایش می‌دهد.

## ۴. خطاهای ممکن

| خطا | کد | راهکار |
|------|-----|---------|
| زمان انتخاب شده قبلاً رزرو شده است | 400 | پیام خطا: «این زمان قبلاً رزرو شده است» |
| کاربر لاگین نکرده است | 401 | هدایت به صفحه ورود |
| خطای سرور | 500 | پیام خطا: «لطفاً دوباره تلاش کنید» |
