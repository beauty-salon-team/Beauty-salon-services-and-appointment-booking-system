مستند تصمیم‌های طراحی و فنی سامانه سالن زیبایی

۱. مقدمه

این مستند تصمیم‌های اصلی طراحی و فنی سامانه رزرو نوبت و مشاهده خدمات سالن زیبایی را توضیح می‌دهد. هدف، طراحی سامانه‌ای ساده، قابل نگهداری و قابل توسعه است.

۲. تصمیم درباره معماری نرم‌افزار

برای این پروژه، معماری لایه‌ای (Layered Architecture) و ساختار یکپارچه (Monolithic Architecture) انتخاب شده است.

این انتخاب به دلیل کوچک بودن پروژه و مناسب بودن آن برای تیم دانشجویی انجام شده است. این ساختار امکان جداسازی رابط کاربری، منطق برنامه و دسترسی به داده‌ها را فراهم می‌کند.

۳. فناوری‌های انتخاب‌شده

* رابط کاربری: React.js
* سمت سرور: Node.js و Express.js
* پایگاه داده: PostgreSQL

React برای ساخت رابط کاربری، Node.js و Express برای پیاده‌سازی APIها و PostgreSQL برای ذخیره اطلاعات مرتبط با مشتریان، متخصصان، خدمات، برنامه کاری و نوبت‌ها در نظر گرفته شده‌اند.

۴. تصمیم‌های طراحی پایگاه داده

اطلاعات اصلی سامانه در موجودیت‌های جداگانه نگهداری می‌شوند:

* مشتری (Customer)
* متخصص زیبایی (Beauty Specialist)
* خدمت (Service)
* برنامه کاری (Schedule)
* نوبت (Appointment)

این جداسازی به سازمان‌دهی اطلاعات و مدیریت ارتباط بین موجودیت‌ها کمک می‌کند.

۵. ارتباط بخش‌های سامانه

ارتباط رابط کاربری با سمت سرور از طریق APIهای مبتنی بر REST انجام می‌شود. این روش، تبادل اطلاعات بین بخش‌های مختلف سامانه را ساده‌تر می‌کند.

۶. تصمیم درباره احراز هویت

احراز هویت کاربران در طراحی سامانه در نظر گرفته شده است. استفاده از JWT برای مدیریت نشست و دسترسی کاربران، در صورت پیاده‌سازی قابلیت ورود، قابل استفاده خواهد بود.

۷. روش توسعه پروژه

توسعه پروژه با رویکرد Scrum و در قالب دو اسپرینت برنامه‌ریزی شده است. در هر اسپرینت، مجموعه‌ای از User Storyها انتخاب و هدف مشخصی برای آن تعیین می‌شود.

۸. قابلیت‌های قابل توسعه در آینده

قابلیت‌هایی مانند پرداخت آنلاین، ارسال اعلان و امکانات مدیریتی بیشتر می‌توانند در نسخه‌های آینده اضافه شوند. در صورت افزایش پیچیدگی سامانه، معماری نیز قابل بازبینی خواهد بود.

۹. جمع‌بندی

تصمیم‌های فوق با توجه به نیازهای فعلی پروژه، سادگی پیاده‌سازی و امکان نگهداری و توسعه در آینده انتخاب شده‌اند.
